LWA MCP / LWA PLUGIN TEST WORKFLOW

Polymino control note

Use the polymino control as a repeatable surface for validating launch, keyboard input, state persistence, and plugin-driven automation against the same seed and score history.

SCOPE Local test only Static browser surface; no provider completion.

WORKFLOW

Recommended operator flow

  1. Open the polymino control.
  2. Use ?seed=12345 for a deterministic launch; a query seed takes precedence over local storage.
  3. Confirm the persisted seed and score summary in the sidebar.
  4. Use Export snapshot to capture an exact board fixture, then Import snapshot to restore it.
  5. Use the action log to confirm visible mcp: and plugin: control events.
  6. Validate keyboard control, hold, rotation, hard drop, and game-over recovery.
  7. Capture the local seed, score, and snapshot JSON after each run.

LWA TESTS

What to verify

  • The dashboard link opens the control page.
  • The control preserves seed, score, and display toggles across reloads.
  • The same seed produces the same initial current and next queue state.
  • Snapshot JSON restores board, queue, hold, score, level, RNG position, and action trace.
  • Export/import failures are announced in the status region and logged as MCP actions.
  • The bag only uses the curated monomino through tridecomino families.
  • The board remains keyboard reachable and readable at mobile and desktop widths.
  • Resetting with the same seed reproduces the same initial bag order.

SCENARIO MATRIX

Repeatable CI-style cases

  • ?seed=1: smallest positive seed and fresh local storage.
  • ?seed=12345: standard deterministic keyboard and snapshot run.
  • ?seed=4294967295: unsigned 32-bit boundary seed.
  • Reload after a hard drop: score, seed, toggles, and action log persist.
  • Import a saved fixture, rotate, hold, hard drop, and export again.
