# Project Doctrine

1. **Tech Adept authority:** 00FACE has final authority over spending, deployment, deletion, provider enablement, tool approval, and doctrine changes.
2. **Local-first evidence:** route decisions, usage, failures, quotas, workflow patterns, and tool origins remain locally auditable.
3. **Free is a routing condition, not a promise:** allocations and model availability are verified at runtime and never treated as permanent entitlements.
4. **No silent financial escalation:** paid and user-pays routes require confirmation by default; fallback across that boundary pauses again.
5. **Capability before popularity:** select by task fit, context, tools, structure, verified behavior, cost, and availability rather than prestige.
6. **Bounded automation:** failover, consensus, pattern generation, and confirmation tokens have explicit ceilings and states.
7. **Truthful state:** proposed, detected, drafted, active, disabled, and verified are distinct states. Queued work is never marked implemented.
8. **Secret containment:** keys never enter prompts, tool output, logs, dashboard payloads, manifests, or generated READMEs.
9. **Primary-model conservation:** auxiliary providers reduce unnecessary Codex/SOL/Terra/Luna usage while allowing justified quality escalation.
10. **Reversible configuration:** routing policy lives in YAML, mutable mode in SQLite, and reusable tools in a versioned user-level library.
11. **Reuse before reinvention:** agents search the library when a task resembles prior work, but current requirements always override generic recipes.
12. **Evidence before automation:** automatic tools require repeated successful observations; confidence and evidence remain visible.
13. **Prompt recipes by default:** pattern detection generates routed recipes and wrappers, not unrestricted code.
14. **Script review gate:** script tools remain drafts until source review and explicit approval; global execution remains disabled by default.
15. **Cross-conversation accessibility:** reusable tools live in the XDG data directory and are exposed through stable MCP and CLI interfaces.
## Credential Doctrine

- Provider secrets belong in the protected Lwa `.env`, never in project source or the tool library.
- First-run discovery is bounded and explicit; never recursively scrape a user home directory for secrets.
- Credential input remains visible by operator requirement and must receive exact-value confirmation.
- Codex OAuth session material is not a general provider API key and must not be repurposed.
- Secret updates are atomic, non-destructive, and preserve mode `0600`.


## Strict preflight authority

No Lwa-managed provider work may begin until prompt finalization, token budgeting, quota evaluation, consensus topology, consent, and model selection are complete and locked. `Working...` is an execution-state declaration, not a planning-state declaration. Dynamic rerouting is forbidden during Working; failure returns control to preflight.
